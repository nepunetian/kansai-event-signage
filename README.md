# 関西イベントサイネージ（フルHD画像版）

Fire TV のブラウザ向けに、**1920x1080 の1画面で情報が収まる**ように調整した版です。

## 今回の変更
- フルHD 1画面固定レイアウト
- ページ全体のスクロールなし
- 左側に注目イベントの大きな画像表示
- 右側にイベントカード6件を画像付きで表示
- 注目イベントは12秒ごとに切替
- 右側一覧は16秒ごとにページ切替
- `events.json` に `image_url` を持てるよう変更
- `update_events.py` でイベント画像URLも収集
- 画像がない場合は `placeholder.svg` を表示

## 画像の取得元
- Walkerplus のイベント詳細ページの JSON-LD `image`
- 取れない場合は `og:image`
- X は添付画像がある投稿のみ `image_url` を取得

## GitHub への更新
1. ZIPを解凍
2. ローカルの `kansai-event-signage` フォルダへ上書き
3. GitHub Desktop で Commit
4. Push origin

## Fire TV での使い方
公開URLを開くだけです。画面全体は固定で、注目イベントと一覧だけが自動切替します。

## 読み込み安定化
`events-data.js` にイベントデータを同梱し、画面起動時はこれを即時表示します。
その後 `events.json` の取得に成功した場合だけ最新データへ差し替えます。
GitHub Pages / Fire TV / ローカル表示で `fetch()` が失敗しても、画面が空になりません。

## 画像表示を安定化
イベント収集時に外部画像を `images/` フォルダへダウンロードし、
`events.json` の `image_url` は `images/xxxxx.jpg` のようなローカルURLへ変換します。
これにより、外部サイトの直リンク制限や期限付き画像URLに影響されにくくなります。

更新後は GitHub Actions を1回手動実行してください。
画像ファイルも自動でコミットされます。

## 収集エンジン v2
公式サイトの取得件数が少なかったため、方式を変更しました。

1. イベント一覧ページ内のリンクを探索
2. 各サイトの sitemap.xml / sitemap_index.xml も探索
3. 詳細ページの Event JSON-LD を解析
4. JSON-LDがない場合は timeタグ、meta、本文の日付を解析
5. 会場・OG画像も補完
6. サイトごとに並列取得
7. `collection-report.json` にサイト別の候補件数・取得件数・エラー件数を記録

これにより、JavaScriptで一覧を描画しているサイトでも、
サイトマップにイベント詳細URLが掲載されていれば取得できます。

## 収集エンジン v3
collection-report.json の結果から、候補URLは見つかるのに parsed=0 のサイトが多かったため、
一覧ページを直接読むフォールバックを追加しました。

- ATC: 月別一覧ページを当月から4か月分取得
- LUCUA: 一覧カードのタイトル・日付を直接解析
- 阪急うめだ本店: 催しスケジュール本文から日付・催事名を解析
- 大丸梅田店: イベントカレンダー本文から催事を解析
- あべのハルカス近鉄本店: 一覧本文フォールバック
- アニメイト: 大阪日本橋店のオンリーショップ絞り込みURLへ修正

詳細ページ解析に失敗しても、一覧に開催日が明示されていればイベントとして採用します。

## 収集エンジン v4
大阪の主要サイトを専用パーサー化しました。

- ATC: `2026.08.01 → 08.23` 形式を直接解析
- LUCUA大阪: 一覧リンクの `8/22(土)〜8/23(日)` を直接解析
- 阪急うめだ本店: `◎9月2日～7日` と `◎9階 催場` を直接解析
- あべのハルカス近鉄本店: `［9月3日→7日］` 形式を直接解析
- それ以外は従来の JSON-LD / HTML / sitemap 解析を継続

`collection-report.json` の notes に `dedicated: 件数` が出れば専用パーサーが動いています。

## 収集エンジン v5 - インテックス大阪強化
インテックス大阪について専用収集を追加しました。

1. インテックス大阪トップページを複数URLバリアントで取得
2. EVENTカードの開始日・終了日・イベント名・説明・会場・画像を直接解析
3. 公式イベントカレンダーだけでは名前が取れないケースを補完
4. 当月から6か月先まで「インテックス大阪 + 月 + イベント/展示会」を公開検索RSSで探索
5. 発見した主催者公式ページのEvent JSON-LD / 本文を解析
6. 会場に「インテックス大阪」が確認できるものだけ採用

`collection-report.json` に `インテックス大阪専用` が出れば動作しています。

## タグ判定 v2
タグの誤判定を減らしました。

- イベントタイトルを説明文より強く評価
- `AR` が `ART` に反応する等の短い英字誤爆を防止
- AI / IT / XR / VR / AR / PC / EV は英単語境界を必須化
- 「車」単独ではクルマタグを付けない
- 「食」単独ではグルメタグを付けない
- タグは主カテゴリ + 明確な副タグのみ
- 最大3タグ
- 収集元で一度付いた古いタグも最終段階で全件再判定

例:
- 美術イベント → 「展示」「美術」
- カスタムカーイベント → 「クルマ」「カスタムカー」
- 声優イベント → 「アニメ・ゲーム」「声優」
- ARTという文字があるだけ → 「AI・IT」は付かない

## v8 日付フィルター修正
「今日」「今週末」の判定を開始日だけでなく開催期間で判定するよう修正しました。

例:
- 9/1〜12/20 のイベントを 9/6 に見る → 「今日」に表示
- 9/1〜9/7 のイベント → 9/6(土)・9/7(日)の「今週末」に表示
- 開始日が過去でも開催中なら対象

## v9 複数カテゴリ対応

従来は1イベントにつき1カテゴリでした。
そのため「鉄道×アニメのコラボカフェ」のようなイベントが
鉄道またはアニメに分類されると「食・グルメ」から消える問題がありました。

v9では `categories` 配列を追加します。

例:
```json
{
  "category": "rail",
  "categories": ["rail", "anime", "food"],
  "tags": ["鉄道", "アニメ・ゲーム", "食・グルメ"]
}
```

フィルターボタンは `category` ではなく `categories` も見るため、
同じイベントが関連する複数のフィルターで表示されます。

グルメ判定も以下を追加:
- コラボカフェ / キャラクターカフェ / 期間限定カフェ
- 物産展 / 北海道展 / 駅弁
- スイーツ / パン / ラーメン / カレー
- 日本酒 / ビール / ワイン
- アフタヌーンティー / ビュッフェ
- チョコレート / ショコラ / アイスクリーム系イベント
